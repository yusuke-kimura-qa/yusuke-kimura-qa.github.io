# ポートフォリオ掲載用原稿：プロフィール・業務経歴

更新日：2026年10月10日

掲載先の目安：トップページに紹介と「経験してきたこと」、下部または別ページに業務経歴とAboutを配置する。

## トップページの紹介

### QAの経験を、使いやすいプロダクトへ。

約5年半、アジャイル開発を中心にソフトウェアテストに携わってきました。機能テスト・リグレッションテストの実行から、QA担当者のレビューを受けながらのテスト分析・設計・テストケース作成まで経験しています。

現在はWindows向けPNGTuberアプリ「Mimica」を個人開発しています。実装はAIと協働し、何を作るか、どう確かめるか、リリースしてよいかを自分で判断しています。

## 経験してきたこと

### 仕様を具体的なテストケースにする

追加機能や業務ルールをもとに、操作手順・入力条件・期待結果を整理。条件分岐や適用時期の変化を踏まえたケースを作成してきました。

### 帳票の表示と内容を確かめる

レイアウトだけでなく、計算結果、日付、事業所情報、文字数による表示崩れ、帳票形式の違いを確認してきました。

### レビューを通して確認観点を詰める

ドメイン固有のルールをQA担当者に確認し、指摘を観点やケースへ反映。不具合報告や既存テストケースの改善にも携わってきました。

## 業務経歴

### 2024年8月〜2025年10月｜訪問看護領域のサービス

外部QAエンジニアとしてアジャイル開発チームに参加。社内Wikiのテスト仕様書をもとに、テスト分析・設計・テストケース作成・実行を担当しました。

主に、訪問看護報酬に関する帳票・提出機能、業務登録画面、報酬計算の検証に携わりました。制度改正に伴う帳票変更では、レイアウトや記載内容、最大文字数での表示崩れに加え、自治体ごとの帳票形式の違いを踏まえて確認観点を追加しました。

業務登録画面では、報酬算定対象と自費の区分による入力項目・選択肢の出し分けや、訪問看護と介護の区分に応じた表示内容を確認しました。

複雑な報酬計算では、シニアQAが主なテスト設計を担当。私はその設計をもとに、訪問日や月途中の公費適用などの条件を具体化し、期待する計算結果まで記載したテストケースを作成しました。業務ルールや計算結果についてレビューを受け、修正を反映しながら進めました。

### 2023年1月〜2024年8月｜複数の短期案件

テスト実行を中心に、案件に応じてテスト設計・テストケース作成・テストデータ作成を担当しました。

B2Bの帳票出力案件では、ウォーターフォール開発において、テスト分析書をもとに設計とケース作成を経験。ほかに、UI/UX観点でのテスト実行や、暗号資産領域のテスト実行に携わりました。

### 2020年3月〜2023年1月｜マッチングアプリ

週3日、1週間単位のスクラムで開発するチームに参加。機能テスト・リグレッションテストの設計とテストケース作成を、QA担当者のレビューを受けながら担当しました。

追加機能の確認内容を具体化するとともに、リグレッションテストへ追加するケースを作成しました。

### 2020年8月〜2022年12月｜医療領域のサービス

マッチングアプリ案件と並行して週2日参加し、機能テスト・リグレッションテストの実行と、取引先のエンジニア・QA担当者への不具合報告を担当しました。

月次の打ち合わせでは、上長とともに既存テストケースの改善案や不具合を分析し、テスト観点一覧の作成に関わりました。

## About

Yusuke Kimura。スマートフォン・光回線の販売職から、ソフトウェアテストの仕事へ転職しました。きっかけは、販売現場で使っていた契約用アプリの使いにくさ。「使う人が困るところを、改善につなげる仕事」に興味を持ちました。

テスターとしてアルバイトで入社し、契約社員、正社員へと登用されました。テスト実行から少しずつ担当範囲を広げ、現在はその経験を個人のプロダクト作りにも活かしています。

Mimicaでは、自分自身を最初のユーザーとして、使う人が迷わないか、変更によって他の機能が壊れていないかを確かめながら開発を進めています。
